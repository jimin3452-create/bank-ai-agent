# 회고

> 공지 제출물 "회고"(설계와 구현 과정에서 배운 점, 어려웠던 점과 해결 과정, 남은 한계와 개선하고 싶은 점). 아래 내용은 저장소의 커밋 기록, `docs/agent-spec.md`의 평가 기록, 2026-11-23 테스트 실행 결과를 근거로 정리했다.

## 1. 배운 점
- **돈이 오가는 기능은 "한 번만, 전부 아니면 전무"가 핵심이다.** 이체를 하나의 트랜잭션으로 묶고, 중복 방지 키(`Idempotency-Key`)와 계좌 잠금을 함께 써야 한다. 응답이 유실돼 같은 요청이 다시 와도 한 번만 처리되고, 서로 반대 방향 이체나 결제와 이체가 동시에 와도 교착·초과 출금이 생기지 않는다는 것을 동시성 테스트로 확인했다.
- **실패 경로도 기록하고 테스트해야 한다.** 잔액 부족 이체는 에러만 돌려주지 않고 `FAILED` 이체로 남기되 잔액과 원장은 바뀌지 않게 했고, 이를 테스트로 고정했다.
- **LLM은 부품이고, 숫자와 권한은 서버가 쥔다.** 모델이 다듬은 답변은 숫자가 초안과 같을 때만 쓰고, 링크가 섞이거나 숫자가 다르면 초안으로 되돌린다. 이체·카드 분실처럼 위험한 동작은 직접 실행하지 않고 값이 채워진 화면 링크로 안내하며, PIN은 항상 사용자가 화면에서 직접 입력한다.
- **에이전트 품질은 눈대중이 아니라 평가 세트로 본다.** 골든 질문과 검색 평가 질문을 먼저 만들어 두니 프롬프트를 바꿀 때마다 좋아졌는지 숫자로 비교할 수 있었다.

## 2. 어려웠던 점과 해결 과정
| 문제 | 원인 | 해결 | 배운 점 |
|---|---|---|---|
| 실제 Gemini에서 골든 질문 5개가 틀림(46/51) | 값 누락(출금 방향·카테고리·받는 사람·상품 이름)과 "방법 질문 vs 실행 요청" 혼동 | 프롬프트에 슬롯 규칙과 예시를 추가했더니 3개만 개선 | 같은 문장을 예시로 넣어도 안 고쳐지면 프롬프트가 아닌 다른 원인을 의심해야 한다 |
| 예시를 넣어도 카테고리·방향이 계속 비어 있음 | 출력 스키마의 선택 필드를 모델이 불확실하면 칸째 생략함 | 스키마를 모든 필드 필수(값이 없으면 null)로 바꿈 → 50/51 | 모델이 보는 스키마의 구조가 답에 영향을 준다 |
| 마지막 1건("왜 거래중지야? 풀고 싶어")이 실패로 남음 | 모델은 [이유 설명 + 해제 안내] 두 행동으로 답했는데 평가는 첫 행동만 봄 | 해제 안내 포함 여부를 보도록 평가 기준을 보정 → 51/51 | 모델이 틀린 건지 평가가 틀린 건지 먼저 구분해야 한다. 다만 기준을 바꿔 맞춘 점수라는 사실은 숨기지 않고 기록한다 |
| 제출 당일 `test_statement_request_sent_and_failed`가 실패 | 테스트에 조회 종료일 `2026-11-10`이 하드코딩돼 있어, 오늘 기준 2일 전 거래가 범위 밖이 됨. 앱 버그가 아니라 테스트 문제 | 종료일을 `date.today()`로 바꿈 → 전체 167개 통과 | 날짜가 들어간 테스트는 시간이 지나면 깨진다. 상대 날짜를 써야 한다 |
| 개발 PC의 PostgreSQL과 포트 충돌 | 기본 포트 5432를 PC에 이미 설치된 PostgreSQL이 사용 | Docker의 호스트 포트를 5433으로 옮김 | 개발 환경 충돌은 문서(README)에 적어 두어야 재현할 수 있다 |

## 3. 남은 한계
- **프론트엔드 자동 테스트가 없다.** 백엔드와 에이전트는 pytest 167개로 확인했지만, 화면은 자동 테스트가 없고 제출 직전의 전체 화면 점검도 하지 못했다.
- **에이전트 테스트는 가짜 LLM으로 돈다.** 실제 Gemini 품질은 골든 질문 평가(`scripts/eval_agent.py`)로 따로 봤고, 제출 직전에는 다시 돌리지 않았다. 또한 평가 기준을 한 번 보정했으므로 51/51은 "기준을 고친 뒤의 점수"다.
- **LLM 데이터 취급.** 거래내역이 Gemini로 전송된다. 이 프로젝트는 가상 데이터만 쓰며, 실제 고객 데이터에는 그대로 쓸 수 없다.
- 열린 이슈(RAG 재사용 범위, 공지 참고 링크 미확인, 와이어프레임 이미지 누락 등)는 [agent-spec.md](agent-spec.md) 12절에 남아 있다.
- 테스트 로그 경고: 테스트용 JWT 키가 짧다(`InsecureKeyLengthWarning`). 운영에서는 32바이트 이상 키가 필요하다.

## 4. 개선하고 싶은 점
- 프론트엔드에 핵심 흐름(로그인 → 이체 → 결과, 에이전트 챗) 브라우저 자동 테스트를 추가한다.
- 골든 질문 평가를 CI에 넣어 프롬프트·모델 버전을 바꿀 때마다 점수를 자동 비교한다. 평가 기준을 바꾼 이력도 남긴다.
- 에이전트가 직접 처리하는 범위(예산 설정 등)를 넓히되, 돈이 움직이는 동작은 지금처럼 화면 승인과 PIN을 거치게 유지한다.
- 와이어프레임 이미지를 보충하고 기획서와 구현 화면을 대조한다.
