# 07. 개발 로드맵

> 일정은 상대 기간(주) 기준 초안. 인원·가용 시간 확정 후 조정.
> 선행 조건: 02 문서 승인, `reference/`에 SQL 원본·features 복사.

## 0. 한 줄 요약
**① 기준 정리 → ② 소비 데이터 기반 → ③ 조회·분석 Agent → ④ 예산·예측·제안 → ⑤ 은행 기능 연결·RAG → ⑥ 품질·보안 검증** 순서. Agent보다 **분류된 소비 데이터**가 먼저다.

## 1. 단계별 계획

| 단계 | 기간(안) | 목표 | 주요 산출물 | 완료 기준 |
|---|---|---|---|---|
| P0 기준 정리 | 1주 | 기존 문서 원문 대조, 02 승인, 카테고리·정책 확정 | 확정 정책표, 기능 ID 대조표 | 02 체크리스트 완료 |
| P1 은행 기본 기능 | (별도 일정) | 기존 A~D 구현 | 기존 명세 기준 | 기존 TC 통과. **Agent 개발의 선행 의존** |
| P2 소비 데이터 기반 | 2주 | 신규 테이블, 분류 파이프라인, 테스트 데이터 | 마이그레이션 설계, 시드 거래 3~6개월치, 분류 규칙 | 샘플 200건 분류 정확도 측정 완료 |
| P3 조회·분석 Agent | 2~3주 | E1, E3, F2(맥락), F3 읽기 안전장치 | Tool 7종, 골든 질의 10종 | 금액 일치율 100%, 권한 TC 통과 |
| P4 예산·예측·제안 | 2주 | E4~E8, 쓰기 확인 흐름 | pending_action, 예산/예측/정기지출 | 확인 없이 저장 불가 TC 통과 |
| P5 은행 연결·RAG | 2주 | F1(화면 이동), G1 | navigate 매핑, 지식 색인, FAQ | 혼합 질의 5종, 인젝션 TC 통과 |
| P6 검증·마무리 | 1~2주 | 통합 테스트, 알림, 리포트 | E9·E10(선택), 문서·시연 | 성공기준 G-N1~N5 점검 |

## 2. 의존 관계

```
P0 ─► P2 ─► P3 ─► P4 ─► P5 ─► P6
P1 ─────────┘ (계좌·거래·카드 데이터와 인증이 있어야 P2/P3 연결)
```
P2의 시드 데이터는 P1이 늦어져도 **독립 생성** 가능 → 병행 개발 가능.

## 3. 리스크와 대응

| # | 리스크 | 영향 | 대응 |
|---|---|---|---|
| R1 | 기존 미정 정책 지연 | 02 C-03~07 임시 가정 유지 | 임시 가정으로 진행 + 확정 시 영향 목록으로 수정 |
| R2 | 거래처명이 불규칙해 분류 정확도 낮음 | E2~E8 품질 | 시드 데이터에 현실적 거래처명, 규칙 우선, 사용자 수정 학습 |
| R3 | LLM 금액 환각 | 신뢰성 | Tool 결과 인용 강제 + 응답 후처리 검증 |
| R4 | 학습용이라 실제 소비 데이터 부족 | 예측·변화 감지 검증 어려움 | 시드 데이터 생성기(패턴 3종: 절약형·과소비형·고정비형) |
| R5 | LLM 비용 | 운영 부담 | 소형 모델 배치 분류, 캐시, 호출 제한 |
| R6 | Agent 범위 확대(이체 직접 실행 등) | 안전 | MVP는 화면 이동만, 직접 실행은 P6 이후 별도 설계 |

## 4. MVP 컷라인

| 포함 | 제외(후속) |
|---|---|
| E1~E8, F1~F3, G1 | E9 이상 소비 알림, E10 월간 리포트 |
