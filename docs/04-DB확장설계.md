# 04. DB 확장 설계

> 원칙: **기존 15개 테이블은 컬럼·제약 모두 변경하지 않는다.** 신규 테이블만 추가한다. (예외: `notifications.type` 코드값 추가, 02 문서 C-01)
> 타입·네이밍은 기존 규칙(UUID/BIGINT, TIMESTAMPTZ, 금액 BIGINT 원 단위, snake_case, 코드값은 영문 대문자) 을 따른다.
> SQL 원본 미열람 → PK/FK 명시 방식은 연결 후 원문 대조해 맞춘다.

## 1. 기존 테이블 중 Agent가 읽는 것 [기존]

| 테이블 | 사용 목적 | 핵심 컬럼 |
|---|---|---|
| users | 본인 식별, 상태 확인 | id, status |
| accounts | 본인 계좌 범위, 내 계좌 간 이체 판정 | id, user_id, account_num, status, balance |
| account_transactions | **소비 데이터 원천** | account_id, transaction_type, transaction_direction, amount, counterparty_name, counterparty_account, memo, transaction_at |
| auto_transfers | 등록된 정기지출 | from_account_id, amount, cycle, run_day, next_run_date, status |
| card_payments | 원본 확인용(분석은 account_transactions 기준) | place, amount |
| account_products, terms | RAG 원문 | |
| notifications | 알림 발송 (코드값 3종 추가) | type, message |

## 2. 신규 테이블 개요 [신규]

```
users ─┬─ budgets ── spending_categories
       ├─ spending_goals
       ├─ recurring_expenses ── auto_transfers(옵션)
       ├─ spending_insights
       ├─ agent_conversations ── agent_messages
       │                      └─ agent_pending_actions
       └─ agent_action_logs
account_transactions ── transaction_categories ── spending_categories
spending_categories ── merchant_rules
rag_documents ── rag_chunks (vector)
```

| 영역 | 테이블 |
|---|---|
| 소비 분류 | spending_categories, merchant_rules, transaction_categories |
| 예산·목표 | budgets, spending_goals |
| 분석 결과 | recurring_expenses, spending_insights |
| Agent | agent_conversations, agent_messages, agent_pending_actions, agent_action_logs |
| RAG | rag_documents, rag_chunks |

## 5. 핵심 쿼리 규칙

**소비 건 정의 (뷰 `v_user_spending` 제안)**
```
account_transactions t
JOIN accounts a ON a.id = t.account_id AND a.user_id = :user_id   -- 본인 계좌만 (P4)
LEFT JOIN transaction_categories tc ON tc.transaction_id = t.id
WHERE t.transaction_direction = 'OUT'
  AND COALESCE(tc.is_spending, true)
  AND NOT EXISTS (SELECT 1 FROM accounts m
                  WHERE m.user_id = :user_id AND m.account_num = t.counterparty_account)
```
- 기간: `t.transaction_at >= :start AT TIME ZONE 'Asia/Seoul'` 방식으로 KST 경계 변환
- 모든 Tool 쿼리는 `user_id`를 **토큰에서 주입**하며 LLM 인자로 받지 않는다.
- 카드 결제 환불(역분개) 처리 여부는 기존 SQL 확인 후 결정 (V-3, V-4)
