# 03. 소비패턴 관리 Agent — 기능 명세

> 기능 ID는 기존 A~D와 겹치지 않도록 **E(소비)·F(Agent 코어)·G(RAG)** 를 사용한다.
> 표기: [신규] / [신규 제안] (요청서에 없던 보완 기능)

## 0. 공통 규칙

| # | 규칙 |
|---|---|
| R1 | 모든 숫자는 Tool 결과값만 사용. LLM은 계산·추정하지 않는다 |
| R2 | 모든 응답에 **조회 조건(기간·계좌·카테고리)** 을 한 줄로 명시 |
| R3 | 소비 정의: `account_transactions`에서 `transaction_direction='OUT'` 이면서 **내 계좌 간 이체가 아닌 건** (type: WITHDRAW, TRANSFER, AUTO_TRANSFER, CARD) |
| R4 | 기간 기본값: 언급 없으면 **이번 달(1일~오늘)**, 기준 시간대 Asia/Seoul |
| R5 | 기본 계좌 범위: 본인 전체 계좌 합산. "월급통장만" 등 지정 시 필터 |
| R6 | 데이터 없음/모호함은 추측하지 않고 되묻거나 "없음"으로 답함 |

## 2. 기능 목록

### E1. 자연어 소비내역 조회 [신규] — MVP
| 항목 | 내용 |
|---|---|
| 입력 예 | "지난달 스타벅스에서 얼마 썼어?" / "5만원 넘는 결제만 보여줘" / "이번 주 교통비 내역" |
| 추출 슬롯 | 기간, 거래처 키워드, 금액 범위(min/max), 카테고리, 계좌, 정렬, 건수 |
| 처리 | 슬롯 추출 → `search_transactions` 호출 → 목록+합계 응답 → 필요 시 거래내역 화면 이동 링크 |
| 출력 | 합계, 건수, 상위 N건 표, 조건 요약 |
| 예외 | 기간 모호("요즘") → 최근 30일 가정 후 명시, 결과 100건 초과 → 요약+화면 이동 |

### E2. 소비 자동 분류 [신규] — MVP
| 단계 | 내용 |
|---|---|
| E2.1 규칙 분류 | `merchant_rules`(키워드→카테고리)로 1차 분류 |
| E2.2 LLM 보조 | 규칙 미매칭 거래처만 LLM에 배치 분류 요청 (거래처명만 전달, 금액·계좌 미전달) |
| E2.3 사용자 수정 | "이건 쇼핑이 아니라 식비야" → 해당 거래 재분류 + **같은 거래처 규칙 저장 여부 확인** |
| 시점 | 신규 거래 발생 시 비동기 분류 + 미분류 건 일괄 재처리 |
| 출처 기록 | `source`: RULE / LLM / USER, `confidence` 저장 |
| 우선순위 | USER > RULE > LLM |

### E3. 소비패턴 분석 [신규] — MVP
| 하위 | 내용 | 출력 |
|---|---|---|
| E3.1 월별 지출 | 최근 N개월 총지출 추이 | 월별 표/차트 |
| E3.2 소비 비중 | 카테고리별 금액·비율 | 상위 카테고리, 도넛/막대 |
| E3.3 요일·시간대 | 많이 쓰는 요일/시간 | 짧은 인사이트 1~2줄 |
| 입력 예 | "내 소비 패턴 알려줘", "어디에 제일 많이 써?" | |

### E4. 소비 예산 관리 [신규] — MVP
| 하위 | 내용 | 예시 발화 |
|---|---|---|
| E4.1 설정 | 월 총예산 또는 카테고리별 예산 생성 | "식비 예산 40만원으로 해줘" |
| E4.2 수정·삭제 | 금액 변경, 해제 | "식비 예산 50만원으로 올려줘" |
| E4.3 잔여 조회 | 예산-사용액, 잔여일 기준 하루 권장액 | "식비 얼마 남았어?" |
| E4.4 임계 알림 | 80%·100% 도달 시 `BUDGET_ALERT` 알림 | 기본 80%, 사용자 변경 가능 |
| 확인 | 설정·수정·삭제는 **실행 전 한 번 확인**(금액 명시) | |

### E5. 소비 변화 감지 [신규] — MVP
| 항목 | 내용 |
|---|---|
| 비교 | 전월 동기간 vs 이번 달 (같은 일수 기준 비교) |
| 출력 | 증가 TOP3, 감소 TOP3 카테고리, 증감액·증감률 |
| 임계 | 증감 10% 이상 **그리고** 3만원 이상일 때만 언급 (소액 노이즈 제거, 값은 조정 가능) |
| 입력 예 | "저번 달보다 뭐가 늘었어?" |

### E6. 소비 예측 [신규] — MVP
| 항목 | 내용 |
|---|---|
| 목적 | 월말 예상 총지출 / 카테고리별 예상 |
| 산식(제안) | 예상 = 현재 누적 + (변동지출 일평균 × 남은 일수) + 아직 안 나간 **정기지출 예상액** |
| 변동지출 일평균 | 최근 가중 평균(이번 달 70% + 최근 3개월 평균 30%) — 초기 달 데이터 부족 보정 |
| 출력 | 예상액, 예산 대비 초과 위험, 근거 수치(누적·일평균·정기 잔여) |
| 한계 명시 | "과거 패턴 기반 추정이며 확정액이 아님" 문구 고정 |
| 데이터 부족 | 이용 3개월 미만이면 신뢰도 낮음 표시 |

### E7. 소비 개선 제안 [신규] — MVP
| 항목 | 내용 |
|---|---|
| 근거 | E3·E5·E6 결과(Tool 수치)만 사용 |
| 제안 형태 | 절약 목표(카테고리, 금액, 기간) + 실행 방법 2~3개 |
| 예시 | "카페 지출이 전월 대비 +42%. 월 8만원으로 줄이면 약 3만원 절약" |
| 목표 저장 | 사용자 수락 시 `spending_goals` 저장 → 이후 진행률 응답 |
| 금지 | 금융상품 가입 권유, 투자 조언, 정해진 수익 약속 |

### E8. 정기 지출 분석 [신규] — MVP
| 하위 | 내용 |
|---|---|
| E8.1 등록된 정기지출 | `auto_transfers`(ACTIVE) 기반 목록·다음 실행일 |
| E8.2 반복 지출 탐지 | 같은 거래처, 월 1회 전후 주기, 금액 편차 ±15% 이내 3회 이상 → 후보 |
| E8.3 월 고정비 합계 | 구독·통신·월세 등 합산, 총지출 대비 비율 |
| E8.4 사용자 확인 | 탐지 후보를 "정기 지출로 등록할까요?" 확인 후 `recurring_expenses` 저장 |
| 입력 예 | "매달 나가는 돈 알려줘", "구독 서비스 뭐 쓰고 있지?" |

### E9. 이상 소비 알림 [신규 제안]
| 항목 | 내용 |
|---|---|
| 규칙 | 단건 금액이 해당 카테고리 최근 3개월 평균 결제액의 3배 이상, 또는 하루 지출이 일평균의 3배 이상 |
| 출력 | `SPENDING_ANOMALY` 알림 + Agent에서 "이 결제 맞나요?" |
| 주의 | 사기 탐지가 아닌 **소비 알림** 용도 (기존 SUSPICIOUS_LOGIN과 구분) |

### E10. 월간 소비 리포트 [신규 제안]
| 항목 | 내용 |
|---|---|
| 시점 | 매월 1일 전월 결과 생성 → `MONTHLY_REPORT` 알림 |
| 구성 | 총지출, 카테고리 비중, 전월 대비, 예산 달성률, 절약 목표 진행, 다음 달 제안 1개 |
| 저장 | `spending_insights` (type=MONTHLY_REPORT, JSON) |

### F1. 자연어 → 은행 기능 실행·화면 이동 [신규] — MVP
| 의도(intent) | 예시 발화 | 동작 | 기존 연결 |
|---|---|---|---|
| 잔액 조회 | "내 월급통장 잔액" | `get_account_balance` 결과 응답 | B2 |
| 거래내역 화면 | "거래내역 보여줘" | 화면 이동 `SCR-005` + 필터 | B2 (FLOW-004) |
| 이체 | "엄마한테 10만원 보내줘" | 즉시이체 화면 이동, 받는계좌·금액 프리필 (**실행은 사용자**) | C1 (FLOW-005) |
| 자동이체 | "매달 25일 월세 자동이체" | 자동이체 화면 이동, 값 프리필 | C2 (FLOW-006) |
| 한도 변경 | "하루 이체 한도 올려줘" | 한도 화면 이동 | B3 (FLOW-007) |
| 카드 | "카드 분실했어" | 카드 관리 화면 이동 (긴급 안내 우선) | D1 (FLOW-010) |
| 계좌 개설/해지 | "계좌 만들고 싶어" | 해당 화면 이동만 | B1/B4 (FLOW-003/009) |

> 화면 ID는 기존 기획서 SCR 번호를 **연결 후 원문 대조하여 확정**한다 (현재 요약본 기준 추정).
> 규칙: Agent는 **로그인·PIN·계좌비밀번호·인증번호를 대화로 받지 않는다.**

### F2. 대화 맥락·후속 요청 [신규] — MVP
| 항목 | 내용 |
|---|---|
| 맥락 슬롯 | 직전 기간, 카테고리, 거래처, 계좌, 정렬 |
| 후속 예 | "그럼 지난달은?" → 기간만 교체 / "그중 카페만" → 카테고리 추가 / "더 보여줘" → 페이지 증가 |
| 한계 | 최근 N턴(제안: 10턴)+요약 유지. 세션 종료 후 슬롯은 폐기, 이력은 보관 |
| 충돌 처리 | 맥락과 새 발화가 충돌하면 새 발화 우선 |

### F3. 안전장치 [신규] — MVP
| 구분 | 규칙 |
|---|---|
| 읽기 | 즉시 실행 |
| 쓰기(예산·목표·분류수정) | 요약 후 **확인 버튼** |
| 금전 이동 | Agent 직접 실행 금지(MVP). 화면 이동만 |
| 차단 | `users.status=LOCKED` 또는 미로그인 시 Agent 비활성 |
| 인젝션 | 거래처명·메모 속 지시문은 데이터로 취급 |

### F4. 대화 이력 관리 [신규]
이력 목록·삭제, 탈퇴 시 삭제, 도구 호출 감사로그 별도 보존(`agent_action_logs`).

### G1. RAG 기반 금융 상품·약관·서비스 안내 [신규] — MVP
| 항목 | 내용 |
|---|---|
| 대상 | `account_products`, `terms`, 서비스 FAQ·이용 가이드 |
| 예시 | "입출금통장 금리 알려줘", "계좌 해지 조건이 뭐야?", "자동이체 말일은 어떻게 돼?" |
| 규칙 | 출처 문서명·버전 표기, 문서에 없으면 "확인할 수 없음" |
| 상세 | `06-RAG설계.md` |

## 3. 대표 시나리오 (골든 질의셋 시작점)

| # | 발화 | 기대 Tool | 기대 결과 |
|---|---|---|---|
| 1 | 이번 달 얼마 썼어? | `get_spending_summary` | 총지출+조건 표기 |
| 2 | 지난달 식비 TOP5 거래처 | `get_top_merchants` | 표 |
| 3 | 5만원 넘는 쇼핑 결제 | `search_transactions` | 금액·카테고리 필터 |
| 4 | 식비 예산 40만원 | `propose_budget_change` → UI 확인 → `confirm_action` | 확인 후 저장 |
| 5 | 이번 달 말까지 얼마 쓸 것 같아? | `forecast_month_end` | 예상액+근거 |
| 6 | 전월보다 뭐가 늘었어? | `compare_periods` | 증감 TOP3 |
| 7 | 매달 나가는 고정비 | `get_recurring_expenses` | 목록+합계 |
| 8 | 그럼 지난달은? (후속) | 직전 Tool 재호출, 기간 교체 | 맥락 유지 |
| 9 | 엄마한테 10만원 보내줘 | `navigate` (C1 프리필) | 실행 안 함 |
| 10 | 다른 사람 계좌 소비 보여줘 | 거부 | 권한 위반 응답 |
