# 확정 정책값 (임의 확정안)

> 작성일: 2026-11-10
> `product-spec.md`와 `agent-spec.md`에 "미정"으로 남아 있던 항목을 이 문서에서 **임의로 확정**한다. 구현과 테스트는 이 값을 기준으로 하고, 팀 논의로 바꾸면 이 문서만 고친다. 충돌 시 이 문서가 `product-spec.md`의 미정 항목보다 우선한다.

## 1. 회원·인증 (A)

| 항목 | 확정 값 |
|---|---|
| 로그인 실패 잠금 | ID/PW 연속 5회 실패 → `users.status = LOCKED`. 성공 시 실패 횟수 0으로 초기화 |
| PIN 실패 잠금 | PIN 연속 5회 실패도 `LOCKED`. PIN 인증(이체·한도 변경 등)에서도 같은 카운트를 사용 |
| 로그인 잠금 해제 | 비밀번호 재설정(이메일 인증번호, 목적 `RESET_PW`) 완료 시 `ACTIVE`로 복구하고 실패 횟수 초기화. DB에 로그인 잠금 전용 목적이 없어 `RESET_PW`를 재사용 |
| PIN 로그인 | 로그인 아이디 입력 후 PIN 6자리로 로그인. 기기 등록 없음 |
| 이상 접속 판단 | ① 최근 30일 접속 기록에 없던 (IP, 기기·브라우저) 조합에서 로그인 성공, 또는 ② 직전 3회 이상 연속 실패 뒤 성공 → `SUSPICIOUS_LOGIN` 알림 1건. 첫 로그인(기록 없음)은 제외 |
| 세션 | 액세스 JWT 30분, httpOnly 쿠키. 갱신 토큰 없음. 무활동 10분이면 프론트가 로그아웃 API를 호출해 자동 로그아웃 |
| 이메일 인증번호 | 숫자 6자리, 유효 5분, 시도 5회 초과 시 폐기, 재발송은 60초 간격 · 같은 이메일·목적당 하루 5회 |
| 정보 변경 | 변경 가능: 이메일(새 이메일 인증번호 필요), 휴대폰 번호, 생년월일, PIN(현재 PIN 확인). 이름은 변경 불가 |
| 회원 탈퇴 제한 | 잔액이 남은 계좌, 해지되지 않은 체크카드·자동이체가 있으면 탈퇴 불가(먼저 해지). 탈퇴 시 `WITHDRAWN`, 로그인 불가, 데이터는 보관 |

## 2. 계좌 (B)

| 항목 | 확정 값 |
|---|---|
| 통장 비밀번호 잠금 | 연속 5회 실패 → `accounts.status = SUSPENDED`(거래중지) |
| 거래중지 해제 | 이메일 인증번호(`UNLOCK_ACCOUNT`) 성공 시 `ACTIVE`, 비밀번호 실패 횟수 초기화 |
| 상태별 허용 동작 | `product-spec.md` 5절 표를 그대로 확정. 거래중지·해지 계좌는 입금도 차단. 거래중지·해지 계좌에 연결된 체크카드 결제는 거절 |
| 이체한도 변경 범위 | 1일 1만원~1,000만원, 1달 1만원~5,000만원, 1일 한도 ≤ 1달 한도. 변경은 PIN 인증 |
| 한도 집계 | 한국 시간(KST) 달력 기준 일·월. 이체 상태 `SUCCESS`와 `PENDING` 합산, 즉시이체와 자동이체 모두 포함. 카드 결제는 이체한도에 넣지 않고 카드별 일일 사용한도로만 제한 |
| 계좌 수 | 회원당 활성 계좌 최대 5개. 상품별 제한(`max_accounts_per_user`)이 더 작으면 그 값을 따름 |
| 상품 가입 조건 | `account_products`에 가입 조건 컬럼 추가(`db/004_product_conditions.sql`): 만 나이 범위, 상품당 최대 개설 수, 조건 설명, 우대금리 조건. 공지의 "상품별 금리와 가입 조건" 요건 반영 |
| 연령 조건과 생년월일 | 생년월일은 가입 시 선택 항목이라, 연령 조건이 있는 상품은 생년월일이 없으면 개설을 막고 "정보 변경" 화면으로 안내 |
| 이자 | 금리는 안내용으로만 표시한다. 이자 계산·지급은 이번 범위 밖 |
| 거래내역 다운로드 | CSV(UTF-8 BOM), 기간 최대 1년, 받을 이메일 기본값은 가입 이메일(형식 검증 후 변경 가능). 발송 실패 시 `FAILED` |
| 해지 후 거래내역 | 보관 기간 제한 없이 조회 가능(읽기 전용) |
| 해지 선행 조건 | 잔액 0원, 활성(해지·재발급됨 제외) 체크카드 없음, 사용 중(`ACTIVE`) 자동이체 없음, 계좌 상태 `ACTIVE`. 정지·분실 상태 카드도 해지 전까지는 연결 서비스로 본다 |
| 개발용 입금 | 은행 외부 입금이 없으므로 시연용 입금 API를 둔다(`DEPOSIT`·`IN` 거래 생성, 개발 환경 전용) |

## 3. 이체 (C)

| 항목 | 확정 값 |
|---|---|
| 이체 인증 | 즉시이체·자동이체 등록·자동이체 해지는 PIN |
| 받는 계좌 | 본 서비스 계좌만 가능. 받는 분 확인 화면에서 예금주 이름 가운데 글자를 마스킹(예: 김*수). 와이어프레임의 '은행 선택'은 쓰지 않음 |
| 이체 입력 검증 | 금액 1원 이상 정수·한도 이내, 출금·입금 계좌 동일 불가, 메모 100자 이내, 수수료 없음 |
| 중복·응답 유실 | 요청마다 중복 방지 키(`idempotency_key`)를 보낸다. 응답이 불명확하면 같은 키로 결과를 조회하고, 같은 키 재전송은 새 이체를 만들지 않는다 |
| 자동이체 실행 | 매일 09:00(KST) 스케줄러가 `next_run_date <= 오늘`인 `ACTIVE` 건을 실행 |
| 자동이체 말일 처리 | 실행일이 그 달 말일보다 크면 말일에 실행(예: 31일 설정 → 30일·28일에 실행) |
| 자동이체 중복 방지 | 중복 방지 키 `auto:{자동이체ID}:{실행일}` + `FOR UPDATE SKIP LOCKED`로 같은 회차를 한 번만 실행 |
| 자동이체 실패 | 잔액 부족·거래중지 등이면 이체 상태 `FAILED`와 사유 기록, `AUTO_TRANSFER_FAIL` 알림. 재시도 없음, `next_run_date`는 다음 회차로 이동 |
| 자동이체 종료 | 종료일이 지나면 `ENDED`. 사용자가 해지하면 `CANCELED` |
| 자동이체 승인 | 등록 때 PIN으로 승인하고 이후 실행에는 추가 승인 없음 |
| 자동이체 시작일 | 등록 당일에는 실행되지 않으므로 시작일은 내일 이후만 가능. 시작일~종료일 사이에 실행일이 없으면 등록 불가. 사용 중인 자동이체는 회원당 최대 10건 |
| 밀린 회차 | 실행기가 멈춰 회차를 놓쳤으면 한 번만 실행하고 이후 회차로 넘어간다(몰아서 여러 번 출금하지 않음) |
| 동시 이체 | 계좌 행을 항상 id 순서로, 이체 기록보다 먼저 잠가 동시 이체에서도 교착·잔액 초과·한도 초과가 없게 한다 |
| 이체와 소비 | 소비 집계에서 **타인 명의 계좌로의 이체만** 소비에 포함(`agent-spec.md` 2절) |

## 4. 카드 (D)

| 항목 | 확정 값 |
|---|---|
| 발급 | 연결 계좌당 사용 가능한 카드(정상·정지·분실) 1장. 카드번호 16자리(Luhn 검증값)를 생성해 AES로 암호화 저장, 유효기간은 발급 후 5년 |
| 인증 | 한도 변경·해외결제 변경·분실 신고·정지·정지 해제·재발급·해지는 모두 PIN |
| 상태 전이 | 정상 ⇄ 정지(해제 가능), 정상/정지 → 분실(해제 불가, 재발급 필요), 재발급 시 이전 카드 `REISSUED`, 사용자가 해지하면 `CANCELED` |
| 해외결제 | 발급 후에도 변경 가능(PIN) |
| 결제 처리 | 은행 외부 카드망이 없으므로 **카드 결제 시뮬레이터**(개발용 API·화면)로 결제를 만든다. 체크카드라 승인 즉시 연결 계좌에서 차감 |
| 결제 거절 | 카드 상태가 정상이 아님, 연결 계좌가 정상이 아님, 잔액 부족, 카드 일일 사용한도 초과, 해외결제 꺼진 카드의 해외 가맹점 |
| 잠금 순서 | 결제·발급·상태 변경은 항상 계좌 → 카드 순서로 잠가 동시 요청에서도 교착, 이중 발급(계좌당 1장), 잔액·한도 초과가 없게 한다. 분실 신고·정지·해지는 계좌 상태와 무관하게 가능하고, 정지 해제·재발급·설정 변경은 정상 상태 카드·계좌에서만 가능 |
| 알림 | 앱 내 알림만 제공(문자·푸시 없음). 결제 성공 시 `CARD_PAYMENT`, 예산 임계 도달 시 `BUDGET_ALERT` |

## 5. 소비·에이전트 (E)

| 항목 | 확정 값 |
|---|---|
| 소비의 정의 | ① 카드 결제(완료된 건) + ② **타인 명의 계좌로의 성공한 이체·자동이체**. 본인 명의 계좌 간 이체, 입금, 일반 출금은 제외 |
| 카테고리 | 식비, 카페·간식, 교통, 쇼핑, 생활·마트, 의료, 문화·여가, 통신·구독, 교육, 송금·이체, 기타. 타인 이체는 항상 `송금·이체`로 고정하고 가맹점 룰·LLM 분류는 카드 결제에만 적용 |
| 집계 기준 시각 | KST 달력 월. 기본 조회 기간은 이번 달 1일부터 오늘까지 |
| 예산 | 월 전체 예산과 카테고리별 예산. 한 달·한 대상당 1개 |
| 예산 알림 | 카드 결제·타인 이체가 확정되는 시점에 동기 계산. 사용률 80%, 100% 도달 시 `BUDGET_ALERT` 각 1회. 중복 방지는 `budgets.alert_level`(0/80/100)로 한다 |
| 챗 기록 | 30일 보관 후 스케줄러가 삭제. 사용자가 "대화 삭제"로 즉시 삭제 가능 |
| 대화 맥락 | 챗 세션 = 대화 스레드. 최근 10턴 + 이전 내용 요약을 모델에 전달. 24시간 무활동이면 새 세션 |
| 되묻기 | 필수 정보가 빠지면 되묻는다. 연속 2회 되물어도 채워지지 않으면 관련 화면 링크로 안내하고 종료 |
| 응답 방식 | 스트리밍 없이 한 번에 응답. 로딩 표시, 서버 타임아웃 30초. 실패 시 재시도 버튼과 관련 화면 링크 |
| LLM 모델 | 의도 분류·답변은 Gemini Flash급, 가맹점 분류는 Flash-Lite급. 정확한 모델명은 구현 시점 공식 문서로 확인해 `.env`로 주입 |
| RAG 기준값(초안) | 조각 약 400자·겹침 50자, 상위 4개 검색, 코사인 유사도 0.55 미만은 근거 없음 처리, 임베딩 768차원. 질문 세트로 조정 |
| 화면 링크 | 에이전트가 URL을 만들지 않고 서버의 **화면 허용 목록**(`api-spec.md` 7절)에서만 생성 |
