# 시드 데이터 설계 (초안)

> 작성일: 2026-11-10
> 목적: 소비 분석·에이전트·RAG를 시연하고 테스트할 **가상 데이터**를 정의한다. 실제 개인정보·거래는 쓰지 않는다(Gemini로 전송되는 데이터이기도 하다).
> 생성 방식: 고정 데이터는 `db/seed/*.sql`, 거래·결제는 `scripts/seed_demo.py`가 고정 난수 시드(`20261110`)로 생성해 매번 같은 결과를 낸다. 생성기는 검증용 기대값(월별 합계 등)도 함께 출력한다.

## 3. 거래 생성 규칙 (기간 2026-05-01 ~ 2026-11-09)

### 3.1 demo_a 월별 패턴
| 종류 | 규칙 | 거래 유형 | 소비 포함 |
|---|---|---|---|
| 급여 | 매월 25일 280만원 입금 | `DEPOSIT`·IN | 아니오 |
| 월세 | 매월 1일 55만원 자동이체 → B-1(demo_b) | `AUTO_TRANSFER`·OUT | **예(타인 이체, 송금·이체)** |
| 저축 이체 | 매월 26일 30만원 A-1 → A-2 | `TRANSFER`·OUT/IN | 아니오(본인 계좌 간) |
| 친구 송금 | 월 1~2회, 1~5만원 → B-1 | `TRANSFER`·OUT | **예** |
| 카페 | 월 12~25건, 4~7천원. **월마다 조금씩 증가**(5월 12건 → 10월 25건) | `CARD` | 예 |
| 식비 | 월 15~25건, 7천~2.5만원 | `CARD` | 예 |
| 교통 | 월 20~30건(1,500원대 교통카드), 주유·택시 가끔 | `CARD` | 예 |
| 쇼핑·생활 | 월 4~8건, 1~12만원 | `CARD` | 예 |
| 구독 | 매월 같은 날 넷플릭스 17,000원, 멜론 10,900원, 통신요금 55,000원 | `CARD` | 예 |
| 이상치 | 8월 1건 쇼핑 45만원, 10월 1건 의료 28만원 | `CARD` | 예 |
| 미분류 가맹점 | 10~11월에 1.4절 비룰 가맹점 5곳 각 1~2건 | `CARD` | 예 |

- 월 소비 규모: 5~9월 약 130~170만원, 10월은 약 200만원(카페·식비 증가).
- 11월(1~9일)은 진행 중인 달: 예산 80% 알림 시연용으로 식비 예산을 40만원, 사용액이 약 32만원이 되게 생성.
- 예산: demo_a에 10월·11월 식비 40만원, 카페 10만원(10월 카페는 초과), 월 전체 150만원.
- 카드 결제는 모두 `card_payments`(요청·완료) → `account_transactions`(`CARD`, `OUT`) → `new_balance` 순으로 일관되게 만든다. 생성 순서는 시간순이며 거래 후 잔액이 어긋나지 않게 한다.
- 해외 가맹점 1건(해외결제 꺼진 카드라 거절 시연은 시뮬레이터로 수행, 시드에는 넣지 않음).

### 3.2 demo_b
- 매월 1일 월세 55만원 입금(`AUTO_TRANSFER`·IN), 카드 소비는 월 30~50건 소규모.

### 3.3 알림·접속 기록
- 알림: `CARD_PAYMENT` 최근 20건, `BUDGET_ALERT` 1건(10월 카페 예산 초과). 자동이체 실패 알림은 시드에 넣지 않고, 잔액을 비운 뒤 `/api/dev/run-auto-transfers`로 재현해 테스트한다.
- 접속 기록: demo_a 최근 30일 정상 로그인 20건(같은 IP·브라우저), 새 기기 로그인은 시연 시 직접 생성.

## 5. 검증 기준
- `seed_demo.py`는 실행 후 `expected_values.json`을 쓴다(월별 총소비, 카테고리별 합계, 타인 이체 합계).
- 테스트는 `agent-spec.md` 2절의 집계 SQL 결과와 이 파일이 일치하는지 비교한다. 특히 다음을 확인한다.
  - 월세(타인 이체)는 소비에 포함되고, 저축 이체(본인 계좌 간)는 제외된다.
  - 카테고리 합계의 합 = 월 총소비.
  - 비룰 가맹점은 첫 조회에서 `LLM` 분류 후 같은 가맹점 재조회 시 LLM을 호출하지 않는다.
